# Авито: управленческая страница и проверка доступности API

Путь: **Авито** в меню Service2, URL `/avito/`. Кнопка «Подключения»
ведёт в существующую страницу «Коммуникации → Каналы связи».

Страница использует **уже сохранённые** `ChannelConnection` и
`AvitoCredential` организации. Новые ключи вводить не требуется.
Отдельные товары и услуги представлены отдельными подключениями, если
они созданы в Service2. Страница ничего не переносит между профилями Авито.

## Первичная диагностика

Подключённый пользователь с правом `can_manage_channels` может запустить
проверку **каждого** подключения кнопкой «Проверить API». Выполняются:

1. Получение/переиспользование access token по существующим зашифрованным ключам.
2. `GET /core/v1/accounts/self` — идентификация владельца ключей.
3. `GET /messenger/v2/accounts/{id}/chats?limit=1&offset=0` — чтение чатов.
4. `POST /messenger/v1/subscriptions` — **только получение** списка webhook;
   совпадение проверяется по секретному хешу Service2.
5. `GET /core/v1/items?per_page=1&page=1` — доступ к списку объявлений.
6. `GET /core/v1/accounts/{id}/balance/` — доступ к балансу (без хранения суммы).
7. `GET /autoload/v4/uploads/last_successful` — доступ к последней успешной автозагрузке.

`POST /messenger/v1/subscriptions` несмотря на HTTP-метод используется
провайдером для чтения подписок; новых webhook не регистрирует.

Все обращения запускаются только по POST из веб-интерфейса с CSRF-защитой.
На GET страницы никаких обращений к Авито нет. Результаты проверок
содержат только ограниченный набор безопасных статусов и кодов в JSON
`ChannelConnection.settings`:
`avito_api_checked_at`, `avito_api_results`, `avito_api_account_id`.
Токены, ответы API, суммы, сообщения и секретные URL не сохраняются.
HTTP 402/403 — недостаточно прав для отдельного метода (возможен тариф),
но не однозначный диагноз причины.

## Диагностика отказа сообщений

- Если авторизация не работает — проверить ключи и доступ к токену.
- Если ID аккаунта не совпадает с сохранённым — проверить привязку профиля.
  Диагностический экран **не исправляет ID автоматически**.
- Если Messenger 402/403 — доступ к чтению чатов запрещён. Перерегистрация
  webhook сама по себе не устранит ограничение.
- Если Messenger доступен, но webhook не найден — перейти в «Подключения»
  и проверить регистрацию подписки.
- Если webhook найден, но сообщений нет — проверить входящие события,
  последний webhook и ручную синхронизацию в «Каналах связи».

Эта версия **не** выполняет плановый мониторинг, синхронизацию объявлений,
рассылку уведомлений об окончаниях тарифов или расчёт продаж. Их следует
проектировать после получения фактических статусов двух аккаунтов.
