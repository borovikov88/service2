# Импорт 1С «Валовая прибыль по месяцам»

Первый этап интеграции принимает ручную XLSX-выгрузку из 1С. Автоматической
синхронизации и API в этой версии нет. Импорт создаёт только отдельные записи
`OneCImportBatch` и `OneCMonthlyProfit` и не изменяет расходы, кассу или
подотчётные операции.

## Доступ и изоляция

Раздел доступен ролям `owner`, `admin` и `accountant`. Каждый batch и каждая
строка связаны с организацией. Объекты другой организации не выдаются даже по
прямому URL.

## Формат XLSX

Поддерживаются `.xlsx` без макросов размером до 15 МБ. Формат определяется
автоматически; пользователю не нужно выбирать вариант выгрузки вручную:

1. горизонтальный multi-month: месяцы находятся в колонках, а строка товара
   преобразуется в отдельную запись для каждого месяца;
2. вертикальный отчёт 1С:УНФ «Валовая прибыль по номенклатуре»: строка месяца
   задаёт текущий период для следующих за ней детальных строк номенклатуры.

Для горизонтального варианта парсер ищет лист и блок заголовков динамически,
поддерживает одно- и многоуровневые и объединённые заголовки месяцев. В
вертикальном варианте поддерживаются произвольный порядок месяцев и пустые
месяцы. Строки месяца, служебные заголовки и точные строки «Итого», «Общий итог»
или «Всего» не импортируются.

Распознаются показатели: количество, выручка, себестоимость, валовая прибыль и
рентабельность. Строка с несколькими месяцами преобразуется в несколько записей
по правилу «одна номенклатура + один месяц».

Поддерживаются русские полные и сокращённые месяцы, `Месяц 2026`, `01.2026`,
`2026-01` и даты Excel. Если год отсутствует в заголовках, он определяется по
параметрам отчёта. Неопределённый год является критической ошибкой.

Числа могут содержать пробелы, NBSP, точку или запятую, скобки для отрицательных
значений и знак процента. Формулы не вычисляются: `openpyxl` открывает книгу с
`read_only=True`, `data_only=True`, без VBA и внешних ссылок.

## Preview → confirm

1. Форма проверяет расширение, ZIP/XLSX-сигнатуру, структуру и лимиты архива.
2. SHA-256 вычисляется потоком.
3. Файл сохраняется в приватное хранилище и создаётся batch.
4. Preview хранит только метаданные, итоги, первые 30 записей и не более 50 предупреждений
   длиной до 300 символов каждое. Число скрытых предупреждений сохраняется отдельно.
   Строки `OneCMonthlyProfit` ещё не создаются.
5. При confirm файл повторно проверяется по SHA-256 и повторно разбирается.
6. Строки создаются через `bulk_create` внутри `transaction.atomic`.

Рентабельность итогов рассчитывается как `общая валовая прибыль / общая
выручка × 100`; проценты отдельных строк не усредняются.

Для вертикального отчёта preview дополнительно содержит layout, список месяцев,
итоги по каждому месяцу и сверку рассчитанных выручки, себестоимости и валовой
прибыли с общей строкой 1С. Расхождение не более 0,05 ₽ по каждому показателю
считается округлением; существенное расхождение создаёт предупреждение, но не
исправляет исходные значения автоматически.

Если выгрузка использует отступы для иерархии, parser выбирает устойчивый
детальный уровень строк и пропускает родительские агрегаты. Это предотвращает
одновременный импорт агрегата и его дочерней номенклатуры. Пустое числовое поле
сохраняется как `None`, а не заменяется нулём.

## Дубликаты и статусы

SHA-256 уникален внутри пары «организация + тип импорта». Подтверждённый или
находящийся в preview файл нельзя загрузить повторно. Failed/cancelled batch
также сохраняет уникальность: повтор возможен только после осознанного удаления
соответствующего batch администратором данных.

Доступные статусы: uploaded, previewed, confirmed, failed, cancelled. При ошибке
confirm транзакция откатывается полностью. Cancel до подтверждения удаляет
приватный исходный файл; confirmed batch отменить нельзя. Файл failed batch
остаётся в приватном хранилище для контролируемой диагностики и удаляется только
в рамках отдельной административной процедуры. При удалении batch (в том числе каскадно
вместе с организацией) его собственный файл удаляется только после успешного commit БД;
rollback сохраняет и запись, и файл.

## Хранение и ограничения

Файлы находятся под `PRIVATE_MEDIA_ROOT/onec_imports/<organization>/<batch>/`
со случайным серверным именем. Публичного URL и функции скачивания нет.
Оригинальное имя хранится только как метаданные.

`source_row_number` является фактическим номером строки Excel. Для одной строки
могут существовать записи разных месяцев; уникальность обеспечивается сочетанием
batch, номера исходной строки и месяца.

Лимиты: 10 листов, 100 000 строк суммарно, 500 колонок, 150 МБ распакованных
данных, 2 000 ZIP-записей и ограничение коэффициента сжатия. Для нестандартной
структуры отчёта может потребоваться адаптация парсера по обезличенному примеру.

## Локальные тесты

Тесты используют отдельный SQLite settings и не подключаются к MySQL:

```powershell
.\.venv\Scripts\python.exe manage.py check --settings=service_site.test_settings
.\.venv\Scripts\python.exe manage.py test pool_service.tests.test_onec_monthly_profit_import --settings=service_site.test_settings
```

Миграцию на локальной или production-базе эти команды не применяют.
