## Проверенные источники

- Модели подтверждают наличие источников `DevelopmentTask`, связанных
  `DevelopmentIteration` (`iterations`) и `DevelopmentTaskEvent` (`events`), но
  в workspace нет файла БД или выгрузки этих таблиц.
- Локальные refs `HEAD`, `main` и `origin/main` указывают на один SHA
  `642e96b517df327adc47e4ac4cb43401f6e34dcd` — merge PR #26. Других доступных
  коммитов нет, поэтому этот shallow checkout не позволяет подтвердить историю
  реализации старых задач.
- Поиск ссылок `DEV-NNNN` в доступных исходниках и истории обнаружил только
  тестовые значения DEV-0002; связи с реальной задачей у fixture нет.

## Точно отсутствующие доступы и данные

- Нет настроенного подключения к БД приложения и нет дампа production БД;
  поэтому невозможно прочитать реальные `DevelopmentTask`, `iterations` и
  `events` или установить, какие ссылки из диапазона фактически существуют.
- Нет GitHub API token/credentials. Доступны только локальные git refs; нельзя
  прочитать перечень PR, их состояние, checks и commits за пределами shallow
  checkout.
- Нет URL, credentials либо read-only snapshot production; нельзя проверить
  deployed revision и пользовательский результат каждой задачи.

Для завершения аудита нужен read-only экспорт указанных трёх таблиц, read-only
доступ к PR/commits/checks репозитория и идентификатор развернутой production
ревизии. После их предоставления строки следует пересмотреть индивидуально; сам
аудит не должен менять статусы задач.
