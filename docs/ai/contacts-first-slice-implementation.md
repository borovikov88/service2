# Контакты: локальный первый срез

Продолжение [плана](contacts-first-slice-plan.md), не публикация/релиз.
База f65cea03c6f19f381b4514d7c3d1ea6fabfbafe4. Пакет карточек лидов не включён.

## Реализовано

- Название страницы/навигации «Контакты», вкладки Компании/Поставщики/Физ лица.
  Компании включают все доступные legal; поставщики — только явно отмеченные
  существующие Client (включая private); физлица — private. Один Client может
  присутствовать в двух вкладках без копирования. Неизвестные типы не угадываются.
- Existing ClientCompanyLink сохраняет несколько компаний на физлицо, должность,
  primary и автоматические связи ИП. Нового справочника людей нет.
- В карточке owner/admin может явно включить/снять supplier. Свежие actor,
  membership, организация назначения и версия проверяются сервером под locks
  organization→client→actor→membership. Нового grant нет. Stale POST возвращает
  409 с предложением обновить карточку; одинаковое текущее состояние — no-op.
  Снятие несуществующей роли не создаёт строку и не блокирует удаление Client.
- ClientBusinessRole хранит состояние/revision; ClientBusinessRoleEvent —
  автора, время и переход. Изменения атомарны. FK PROTECT удерживают историю;
  штатное удаление связанной карточки объясняет запрет вместо HTTP500.
- Merge сохраняет исходный audit и переносит активную роль на target, объединяя
  совпадения. Запись merge с переносом роли требует actor; автоматической
  классификации, удаления history или изменений 1С нет.
- Серверные поиск, счётчики и страницы по50 строк для каждой вкладки;
  отдельная серверная страница сотрудников объектов. Фильтры прав и поиск
  применяются до count/LIMIT/OFFSET. HTML содержит только текущие страницы,
  без скрытого полного справочника или search_text. URL сохраняет tab/query/page.
- Связи выбираются только для ID текущих страниц: до20 на карточку плюс один
  индикатор продолжения через SQL Window. Все связи доступны через карточку;
  поиск включает весь разрешённый набор связей, даже за пределами превью.
- AJAX с debounce300ms, AbortController и generation guard, сохранением фокуса,
  восстановлением back/forward и повтором после ошибки. Ответ private/no-store.
- Поиск сохраняет национальные телефонные aliases 8…/7…/+7… без превращения
  явного международного +8… в российский номер. Это только поиск, не matching
  личности или автоматическое объединение. Пустой результат фильтра поставщиков
  отличается от отсутствия назначенных ролей.

## Права и установленные риски

На исходном main список допускал пользователя со staff-ролью в одной организации,
но выбирал Client во всех его membership организациях. Теперь список ограничен
теми org, где именно текущая роль входит в существующий staff-набор.

На исходном main ClientCompanyLink выбирался по доступности хотя бы одной стороны;
карточка и update/delete также могли использовать некорректную foreign/merged
связь. Теперь обе стороны должны быть active, доступны, иметь корректные типы
и одну organization. Скрытые связи не попадают в search_text и не изменяются
сбросом primary. Существующие данные не исправляются/удаляются автоматически.
Эти два дефекта предшествовали пакету; воспроизведены на синтетических данных.
Наличие таких строк или фактическая утечка в production не проверялись.

При ревью нового кода дополнительно устранены неправильный выбор первой org
для проверки оплаченного доступа, устаревший actor, запись при пустом no-op и
обратный merge порядок locks. Это найденные до публикации дефекты черновика,
не утверждения об инциденте в production.

Client.private — физлицо, НЕ личная видимость. Пакет не импортирует личную
телефонную книгу и не выдаёт дополнительных разрешений на звонки/диалоги.
Существующая org-видимость Client остаётся; приватная адресная книга требует
отдельного сквозного permission-контракта. Supplier не управляет intake:
автолиды/cohort/cutoff, классификация обращений и «Не продажа» не изменены.

## Миграция и откат

0160 добавляет две пустые таблицы, без RunPython/backfill, ALTER Client или
переноса PK/FK. Client IDs, onec_ref и существующие связи сохраняются.
Preservation test сравнивает полные Client/Profile/Pool/ServiceTask/CrmItem строки
до/после; остальные финансовые таблицы не изменяются этой миграцией. Это не
полный restore-test финансовой БД. Обратная миграция проверяется только на пустых
новых таблицах тестовой БД. После появления ролей/аудита откат приложения должен
сохранить0160 и данные; reverse/drop недопустимы без отдельного решения.

## Gates и границы

- Предыдущая локальная regression: 80 tests, 78 PASS, 2 skipped (реальные row locks).
  Включены карточки, merge, CRM sync, shell, call privacy и новые security tests.
- Реальный Chromium: supplier add/remove, tab/search/page/reload, связанное лицо,
  53 компании, viewport1440/390, dark; только синтетический локальный server.
- Migration test: synthetic preservation и empty-schema reverse/forward.
- Check, makemigrations check (без незаписанных изменений), JS syntax, diff check.
- MySQL race tests добавлены: competing writes и ожидание held merge-org lock
  с проверкой merged alias после ожидания. SQLite skip не означает PASS.
- Оба новых DB-модуля/roles/preservation включены в явный MySQL workflow,
  browser — в существующий закреплённый Chromium шаг. Никакие guards не убраны.
- Локально Python3.12, установленный Chromium154 через прежний разрешённый shim;
  MySQL отсутствует. Полный exact-head CI/MySQL/pinned Chromium остаются gates.
- Независимое ревью требуется для финального diff; локальные логи в scratch,
  без production данных. Публикация/merge/deploy/production migration не разрешены.
