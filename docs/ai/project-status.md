## Переход на тарифный Codex — актуальное решение

Владелец потребовал использовать купленные кредиты Codex вместо отдельного
OpenAI API. Базовый main этой задачи: `b0ff6aa9d0602cffbeee2c20257460bc78dca3c7`
после merge PR №93. GitHub CI этого main: 861 тест, 2 пропущены; deploy skipped.
Диагностика PR №92 дошла до `call_model` и дважды получила OpenAI HTTP 429
(run `33997700563`). Пополнение API для продолжения выбранного пути не требуется.

Подготовлен вывод API workflow из эксплуатации и блокировка серверного
API-клиента разработки/ревью. Используется штатный Codex Code review.
Нативный бот завершил PR №92 на `b0ea2e4` без серьёзных замечаний по команде,
отправленной ведущим через GitHub connector с разрешения владельца:
https://github.com/borovikov88/service2/pull/92#issuecomment-5555569709
Это реальное штатное ревью, но не формальный GitHub APPROVED и не deployment.
Подробности и ограничения — `codex-direct-flow.md`.
Изменения пока описывают подготовленный код: публикация/merge проверяются
отдельно. Production и его `.env` не изменялись. Старые статусы ниже исторические.


## Дополнение: проверка после объединения PR №90

Владелец объединил PR №90, remote main —
`38050cb5cfb4dfd1ddd2bca403d4bbedab782a95`. Новый workflow run `33971063298`
завершился failure до создания jobs. Проверка токена не выполнялась.
В workflow выявлено недопустимое использование `runner.temp` в job-level env;
контекст runner разрешён в step env, но не в job env. Источник:
[GitHub context availability](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#context-availability).

Исправление переносит путь artifact в env двух исполняемых шагов и в upload
with. Добавлен regression test и отдельный CI-шаг actionlint `1.7.12` для
`direct-pr-review.yml` и `ci-deploy.yml`, с проверкой SHA256 официального архива.
23 теста прошли локально; отдельный проверяющий принял исправление и CI-шаг.
Фактическая проверка actionlint в GitHub и подключения бота ещё требуется.
Токены, production, финансовые данные и 1С в этой задаче не изменялись.

## Подтверждено кодом и локальной историей Git

- Django 5.1-приложение имеет обычный вход по `/accounts/login/`, глобальное
  перенаправление неавторизованных запросов на вход и серверные проверки
  финансовых возможностей.
- Есть страницы финансового обзора, валовой прибыли, ДДС, ФОТ, контроля
  себестоимости, операций, отчёта расходов и данных 1С.
- Единственный найденный в текущих URL/view-коде ручной экспорт относится к отчёту расходов по адресу
  `/finance/reports/export/`; он формирует XLSX с теми же месячными фильтрами и
  доступен пользователю с правом управления финансами.
- Аналитика валовой прибыли, ДДС и ФОТ отображается в браузере. Отдельной
  выгрузки аналитических наборов или документированного read-only API для
  внешнего советника в текущем коде нет.
- Роль `accountant` существует, но это **не роль только для чтения**: она входит
  в management-набор и может импортировать данные, подтверждать/редактировать
  финансовые операции, управлять кассой и закрывать периоды в пределах своей
  организации. Выдавать её внешнему советнику как read-only нельзя.
- Все найденные финансовые guards сначала определяют организацию пользователя,
  затем проверяют capability. Запрос ограничивается организацией, которую
  текущая `organization_for_user()` выбирает через `.first()`; поведение
  пользователя с несколькими организациями требует отдельной проверки.
- Миграции `0095`, `0096`, `0097`, `0098` и `0099` присутствуют в текущем коде.
  `0099` добавляет режим автоматического применения и поля синхронизации.
- Merge `30f9c746` (PR #53, Finance Overview V1) присутствует в локальной
  истории, но текущий HEAD существенно новее него.
- Последний merge содержит реализацию атомарного refresh/apply 1С и тесты. Само
  наличие реализации не доказывает, что миграция применена или задача работает
  на production.

## Проверено без доступа к рабочим данным

- Локальное окружение не содержит `DB_*`/`ONEC_*` переменных. Подключение к
  рабочей БД не предпринималось, команды миграции/импорта не запускались.
- Публичный адрес из старого отчёта был проверен только неавторизованным HTTP
  запросом. Сетевой proxy окружения отклонил CONNECT с 403, поэтому доступность
  production, страницы входа и отчётов снаружи **не подтверждена и не
  опровергнута**.
- Без учётной записи и рабочей сессии не проверены наличие конкретной
  организации, дата последнего импорта, полнота периодов и контрольные суммы.
- Подключённых MCP resources/templates, browser tool или service2 connector нет.
  Поэтому чат сейчас не имеет машинного канала к отчётам независимо от ролей.
- Локально подготовлен `/mcp/test/` с одним нефинансовым инструментом и без
  обращений к БД. Он проверен Django tests и локальным HTTP-вызовом, но не
  опубликован, не развёрнут и не вызывался из целевого облачного чата.

## Область разрешений этой передачи

Текущая задача разрешала чтение кода и Git-истории, безопасные локальные
проверки, документирование и подготовку предложения read-only доступа. Она не
разрешала бизнес-правки, импорт 1С, доступ/изменение рабочей базы или deployment.
Эти ограничения относятся к данной задаче и не заменяют отдельные разрешения
для будущих точно определённых операций универсальным разрешением или запретом.

## Автоматизация публикации — подготовлено в коде

`development-codex.yml` публикует PR и явно запускает CI для созданного
`GITHUB_TOKEN` head. Серверный poller после независимого AI review готов
публиковать approval отдельной GitHub identity и включать auto-merge точного
head. Push/merge/deployment этой копией не выполнялись; работа на GitHub и
hosting остаётся неподтверждённой до настройки credentials и первого прогона.

Подтверждённый вход штатного цикла — карточка `DevelopmentTask` в service2.
Сообщение из этого Codex-чата само такую карточку не создаёт: в среде чата нет
подключённого service2 tool/API. Поэтому задачи, выполняемые непосредственно в
этом чате, ведущий публикует штатным PR-механизмом Codex, но подключение их к
production poller без отдельного ingress пока не утверждается.

Проверка PR №87 из текущей среды также заблокирована: remote и GitHub CLI auth
отсутствуют, HTTPS получает CONNECT 403. Локальный HEAD `66fcfe5` подготовлен
для обновления существующего PR через кнопку Codex **Update PR**, но актуальные
base/head и состав файлов PR внешним вызовом не подтверждены. Подробный
fail-closed порядок записан в `docs/ai/codex-direct-flow.md`.
