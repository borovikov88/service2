# Исходящие Авито Услуг: отдельная эксплуатационная проверка

Область текущего выпуска — подключение 4, аккаунт 446312402. История XML,
фотографии и расписание мониторинга аккаунта не являются зависимостью ответа
менеджера. Тихие часы уведомлений владельцу не применяются к явно отправленному
ответу клиенту.

## Чтение фактов

Защищённый workflow `avito-outbox-readonly.yml` запускается после успешного
штатного main-deploy либо вручную с точным подтверждением SHA. Он использует
текущий main, успешный production CI, preflight, существующий SSH-ключ и проверку
known_hosts. Фиксированная команда не отправляет сообщения и не меняет очередь.

Инцидент выбирается по одной минуте UTC, направлению и подключению. Только одна
строка допускает чтение истории соответствующего диалога; тело и UUID дополнительно
сверяются по заранее согласованным SHA-256. Ноль, несколько строк или несовпадение
не дают разрешения на отправку. В публичной квитанции остаются локальный ID,
статус, попытки, закрытый код ошибки, отпечаток тела и признаки доказательств.
Текст, собеседник, диалог, provider ID, токены и ответы провайдера не печатаются.

CLI-проверка crontab относится только к текущему пользователю хостинга. Отсутствие
CLI или отказ не доказывают отсутствие задания в панели Beget, системном cron
или другом планировщике. Достоверность panel-задач явно остаётся неизвестной.

## Один исходный ответ

`recover_avito_original_reply` доступен только защищённому оператору из точного
main с реальным маркером коммита `[avito-outbox-original-20261025]`. Добавлять
маркер можно только после независимого review и зелёного CI фактического head.
Это не общий инструмент повторной отправки.

Уникальная исходная строка должна совпадать по минуте, подключению, account,
организации, SHA-256 тела и UUID диалога. Отправитель должен сохранить право
ответа. Перед действием читается история Авито. Подтверждённое совпадение
сохраняется в той же строке через общий atomic CAS, без второго POST.

Только полное отсутствие совпадений вместе с pending, нулём попыток и отсутствием
provider ID допускает один вызов существующего обработчика. Он снова читает
провайдера, получает single-flight claim и повторяет проверки непосредственно
перед POST. Снимок и фиксированный guard защищают от изменения текста, диалога,
прав и подключения между проверками. Сеть никогда не вызывается внутри atomic.

При неопределённом результате строка не возвращается слепо в очередь. Отдельный
durable ledger также блокирует повтор команды после обрыва. Полученный provider
ID означает приём Авито, а не прочтение клиентом. Поле send_function_invocations
означает вход в штатный метод отправки; оно само по себе не доказывает HTTP POST
или доставку. Доказательство приёма — подтверждённый ID и состояние исходной строки.

Выпуск не изменяет товарное подключение, не создаёт новый ответ, не рассылает
старую очередь и не выполняет платные операции.
