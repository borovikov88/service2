# Проверка реальной фотографии без публикации

Этот сценарий дополняет проверки загрузчика и прежний synthetic storage probe.
Он не считает их выполнением пользовательского сценария и не подтверждает
изменение фотографии на Авито.

## Границы

Только подключение 4, аккаунт 446312402, текущая организация и действующий
владелец из проверенной настройки рабочего места. Ключи, организация, права,
ревизия, полное содержимое черновика и опубликованного снимка, объявление и
выбранная исходная ссылка привязаны к короткоживущей подписи. Другие подключения,
произвольные фотографии, URL, текст, цены, публикация и вызовы изменения Авито
этим маршрутом недоступны. Общую пользовательскую сессию он не создаёт.

Источник — уже существующая фотография одной и той же пары Id/AvitoId,
одновременно указанная в текущих черновике и опубликованном снимке Service2.
Это не доказательство фактического содержания карточки со стороны Авито.
Если API не возвращает фотографии, визуальное сравнение в кабинете остаётся
ручным действием с указанием времени и источника.

## Read-only до выполнения

`pool_service.avito_services_media_livecheck.media_release_source(connection)`
сам получает проверенного владельца, выбирает существующую общую фотографию,
читает её через прежний защищённый загрузчик (либо локально для своего
изолированного файла) и возвращает только:

- scope_valid, source, source_in_published, photo_count, readable;
- format, width, height, bytes, checked_at.

Изображение декодируется с прежними ограничениями: JPEG/PNG/WebP, 8 МиБ,
20 млн пикселей. Транспорт сохраняет прежние проверки DNS/IP, запрет
редиректов и ограничение времени. Функция не сохраняет файл, настройки или
кэш; не возвращает URL, фото, хеш или токен.

## Защищённый пользовательский сценарий

После review конкретного пути оператор на сервере создаёт токен
`make_media_livecheck_token(connection, actor, avito_id)` для согласованного
существующего объявления. Подпись действительна 120 секунд. Токен передаётся
только JSON-телом HTTPS POST на
`reverse('avito_services_media_livecheck')`. Не печатать токен, не передавать
его в URL, логи, workflow inputs или чат. Маршрут не принимает других полей.
Оператор проверяет канонический origin и не следует перенаправлениям.

В реальном web-процессе, под общей блокировкой подключения/фида:

1. Повторно проверяются права и вся привязка подписи.
2. Читается согласованная существующая фотография.
3. Через текущий обработчик загрузки сохраняется настоящий файл изображения.
4. Текущий приватный preview-handler возвращает JPEG, размер и SHA-256 совпадают
   с новым файлом. Публичный обработчик должен вернуть 404.
5. Текущий редактор сохраняет новый файл первым (обложка); проверяется точный
   порядок и неизменность всех остальных полей.
6. Тем же редактором сохраняется прежний список фотографий. Полное содержимое
   исходного черновика должно совпасть, опубликованный снимок и его настройки
   остаются прежними.

Исходные 10 фотографий временно заменяются списком из новой обложки и первых
9 старых, затем восстанавливаются все исходные 10. Превышения лимита нет.
Если форма нормализовала бы старый текст или ссылки, сценарий прекращается
до записи: текст и цена не должны измениться.

Успешный результат оставляет две неизменяемые записи истории и один приватный
asset. Это позволяет увидеть сохранённый порядок, исходное/восстановленное
содержимое и автора. Публичная фотография и опубликованный XML не меняются.
Ревизия увеличивается на два. Повтор той же действующей подписи возвращает
сохранённый протокол без повторной загрузки и новой истории. Содержимое черновика восстановлено точно, служебные время,
автор и ревизия отражают реально выполненную проверку.

При любой ошибке транзакция откатывает весь черновик, историю и новые asset
records. Удаляются только новые файлы этой попытки; уже существующие неизменяемые
файлы не удаляются. Внешнее чтение ограничено 10 секундами и выполняется под
блокировкой; обработчик не запускает публикацию или автозагрузку.

## Timeout и неопределённый ответ

Перед HTTP POST оператор сохраняет поколение запуска и
`operation_id = hashlib.sha256(token.encode('utf-8')).hexdigest()` в своей
защищённой записи состояния. Успешный маршрут сохраняет протокол с этим ID,
текущей привязкой ключей/аккаунта/организации/владельца и ID фида в
`connection.settings['avito_services_media_livecheck_v1']` в той же транзакции,
что сохранение и восстановление черновика. Хранятся последние восемь протоколов;
другие настройки не перезаписываются.

При потерянном HTTP-ответе вызывать только read-only
`media_livecheck_receipt(connection, operation_id)`. Он возвращает точный
протокол либо None, повторно проверяя текущие права и привязку. Срок токена
не ограничивает последующее чтение протокола. Новый токен/повтор мутации
после timeout автоматически не создавать. Отсутствие записи не доказывает
неисполнение: запрос может ещё работать; состояние остаётся неопределённым.
Изменение привязки запрещает использовать прежний протокол. Сохранение
других настроек оператором после ответа должно начинаться с новой заблокированной
строки подключения, чтобы не затереть атомарную запись результата.

## Что означает протокол

Ответ сохраняет время, пару ревизий и записей истории, совпадающие хеши
черновика до/после, отдельный хеш опубликованного снимка и считанной исходной
фотографии. URL, секреты и содержимое карточки не возвращаются.

`upload_saved`, `private_preview_verified`, `cover_order_saved`,
`original_draft_restored` и `published_unchanged` означают реальное выполнение
существующих permissioned HTTP-view обработчиков внутри подписанного HTTPS
запроса. Они не означают клики браузером: `browser_clicks_verified=false`.
Фактическое содержание на Авито не меняется и не проверяется:
`provider_content_verified=false`, `image_publicly_available=false`.

Для браузерного acceptance отдельно открыть редактор как владелец, убедиться
в загрузке, превью и управлении обложкой/порядком. Сам подписанный протокол
не доказывает работу DOM, JavaScript и браузерной cookie/CSRF-сессии. Общие
пользовательские upload/edit маршруты сохраняют обычные login и CSRF-защиты.

## Проверки

Отдельный test module `test_avito_services_media_livecheck` проверяет девять
сценариев: сохранение/точное восстановление, read-only receipt, подпись/срок,
изменение области и прав, безопасный повтор, точную сверку после timeout, откат с удалением только новых файлов,
10 фотографий, некорректное/слишком большое изображение и приватный адрес.
Внешний транспорт подменён безопасным fixture; CI не считается проверкой
рабочего аккаунта. Старые SSRF/format/storage тесты остаются самостоятельными
регрессиями и не выдаются за новый реальный пользовательский сценарий.

## Безопасная диагностика транспорта

Read-only readiness сохраняет прежние проверки редактора и не создаёт новый
токен или загрузку. При ошибке чтения тот же единственный ограниченный GET
возвращает фиксированные reason/phase, HTTP-статус и только безопасные категории.
Исходные URL, адреса DNS, заголовки, тело ответа и текст исключения не выводятся.

transport содержит ровно: reason, phase, http_status, source_scheme, path_ascii,
dns_family, dns_answer_count, selected_ip_family, response_format, declared_bytes,
received_bytes, io_errno, https_upgrade_followed, host_relation. Неизвестные значения — null. Счётчик DNS (1–32) и
семейство показываются только после проверки всех адресов как публичных.
Размеры ограничены 8 МиБ + 1, errno — 0–4095; MIME представлен закрытой категорией.
Ошибка HTTP не становится успешным чтением. Единственное разрешённое
исключение для фотографии — канонический переход HTTP→HTTPS, описанный ниже.
Сертификат/SNI и фактический IP сокета проверяются как прежде. Успех подменённого
тестового транспорта не считается доказательством доступности рабочего фото.

## Единственный допустимый переход для изображения

Только исходный GET изображения по HTTP со стандартным портом 80 может один
раз обработать ответ 301 или 308. В ответе должен быть ровно один непустой
Location: абсолютный HTTPS со стандартным портом 443, тем же IDNA/lower
hostname либо его точной DNS-парой с одним ведущим www. (в обе стороны),
и точно теми же сырыми path и query. Относительные ссылки, userinfo,
фрагменты (включая пустой #), пробельные/управляющие символы, произвольная смена
hostname, trailing dot, повторный www., IP↔DNS, смена порта, пути или query
отклоняются. DNS-пара www. проверяется буквальным сравнением полного базового
имени; регистрируемый домен/суффикс и другие поддомены не сворачиваются.
Любой второй переход и перенаправление исходного HTTPS отклоняются.

Первый ответ и сокет закрываются без чтения HTML. Целевой hostname заново
разрешается в DNS; все адреса должны быть публичными. Новый TLS-сокет закреплён
за проверенным числовым IP и проверяет сертификат/SNI фактического целевого
hostname; HTTP Host также относится к целевому имени.
Оба обращения используют один прежний абсолютный deadline, общий лимит
размера окончательного изображения и прежние ограничения декодирования.
Cookie, Authorization, Referer и ответные cookies не переносятся.

Исходная одобренная строка ImageUrls, её hash/fingerprint и содержимое
черновика/опубликованного файла не меняются. source_scheme в диагностике
всегда относится к исходной строке. https_upgrade_followed становится true
только после проверки Location, повторного DNS, успешного TLS и отправки
разрешённого HTTPS GET. false означает, что такой GET не отправлялся;
null — что наблюдение не выполнялось (например, прежняя сохранённая запись).
source metadata сохраняет только этот дополнительный optional scalar;
полный transport в историю не копируется. host_relation — закрытая
диагностическая категория same/www_alias/other/unknown, не hostname.
www_alias разрешает только описанную однократную точную DNS-пару; все прочие
условия Location и повторная проверка целевого DNS/TLS остаются обязательными.

Эта политика касается только изображений. Транспорт копии XML и signed
operator POST остаётся без перенаправлений. Успех тестовых подмен не заменяет
реальный read-only GET и декодирование рабочего фото перед новым токеном/POST.
