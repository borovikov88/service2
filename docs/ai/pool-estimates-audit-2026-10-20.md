## Выполнено в этой ветке

1. От нуля до трёх источников нагрева. Старое scalar `heating` читается без миграции;
   новое `heating_types` имеет явный приоритет. На каждый источник — полная мощность
   первого прогрева, без деления на число приборов. Общие строки монтажа/обвязки
   не клонируются. Системные отключения обратимы; ручные исключения, цены и existing
   сохраняются. Validate/load не добавляют аксессуары к старым snapshot.
2. Для теплообменника добавлены отдельные циркуляционный насос и электромагнитный
   клапан. Они не участвуют в расходе фильтрации. **Технический автоподбор этих
   аксессуаров пока не выполнен:** в исходных данных нет первичного контура и
   подтверждённых характеристик каталога. Цена остаётся неизвестной, показано
   предупреждение; пользователь может выбрать товар вручную через каталог.
3. Общий ценовой выбор после технического фильтра: один кандидат — во всех КП;
   два — дешёвый/дорогой/дорогой; больше — дешёвый/средний/дорогой. Для нагревателей
   сравнивается минимальная достаточная мощность, для фильтрации сохраняется
   ограничение 1,25× минимальной достаточной производительности. Для закладных
   сохраняется выбранный в каждом КП профиль материала/отделки.
4. Организация убрана из параметров. Контекст страницы берётся из проверенного
   URL, доступного сохранённого проекта или ранее выбранного контекста сессии;
   без них — из первой доступной организации. Явная чужая организация отвергается.
   API продолжает проверять членство при каждом запросе, ставки остаются scoped.
5. Явные внутренняя длина/ширина, полная внутренняя высота H, глубина воды hw,
   толщина стен t и плиты b. Новые поля не заполняются скрытыми предположениями.
   Полная модель пока только с горизонтальным дном; hw ≤ H. Без H сохраняется
   старая модель и предупреждение. Без толщин бетон неизвестен.
6. Бетон плиты = (L+2t)(W+2t)b; стены = ((L+2t)(W+2t)−LW)H.
   Общий бетон округляется один раз после сложения. Внутренняя отделка = LW+2(L+W)H.
   Работы ceil(area), плёнка/геотекстиль каждый ceil(area×1,15), все через Decimal.
   Автоматические бетонные объёмы применяются к материалу и работе бетонирования;
   цены материала не выдумываются. Ручные количества, включая ноль, сохраняются.
   При смене размеров они получают предупреждение об устаревании. При удалении
   исходной толщины автоматический объём бетона становится неизвестным.

### Общая ставка работы — решение о базе ещё требуется

Требование единой ставки принято, но изменение ставок **не включено** в эти
коммиты: ожидается выбор владельца между конфликтующими исходными тарифами.
Задан вопрос, использовать ли 2000/200/70000 ₽ либо оставить общие значения
неподтверждёнными. Существующие цены не выравнивались автоматически.

Предлагаемое правило до любой миграции данных:

1. Общая ставка имеет ключ организация + код работы + единица + тип отделки;
   вариант КП не входит в ключ. Количество и сумма остаются индивидуальными.
2. Согласованная общая база используется только в новых строках/расчётах.
   Подтверждённое повышение становится общим ориентиром следующих расчётов;
   более низкая явная цена считается скидкой конкретной строки и не снижает память.
3. Для существующих разных сохранённых ставок сначала показать конфликт владельцу.
   Предложение — принять максимальную подтверждённую повышенную ставку, не меньше
   согласованной базы; это правило пока **не применено** к данным.
4. История, явные скидки и уже заполненные ставки в текущих сметах не переписываются.
   До утверждения базы/правила не удалять записи памяти с прежним variant-key.

Качественная градация оборудования и предпочтительные модели также остаются
предложением: не приписывать ресурсу/материалам преимущества по одной цене.
Сейчас действует воспроизводимая фильтрация доступных характеристик и ценовой
выбор, не ИИ-подбор. Номинальные кВт теплообменника не подтверждают мощность при
неизвестных температуре и расходе теплоносителя. Типовой насос 25/4 не применяется
слепо ко всем теплообменникам. Предварительное автоматическое заполнение реальными
моделями с отдельным статусом проверки первичного контура ещё требует доработки;
добавление количества пар не объявляется завершением подбора моделей.

### Предварительный подбор первичного контура

Реализован подбор реальных моделей из feed по проверенным SKU, бренду и полной
модели: GPD25-4S-180 (32528), GPS25-5-180 (35398), клапаны 2W31 DN20/25/50
(19817/19818/54203). Цены берутся исключительно из текущего каталога. Источники
модельных характеристик указаны в estimate_primary.py; карточки не изменяются.
Отдельно задаются присоединения насоса и клапана: без них диаметр не угадывается.
Known mismatch температуры, питания и предельных Qmax/Hmax отсекается до цены.
Для воды расход предварительно P/(1.16·ΔT); если задан больший ручной расход,
учитывается больший. Ни Qmax/Hmax, ни номинальные кВт не являются рабочей точкой.
Эконом предпочитает простой GPD, стандарт/премиум — GPS с регулированием среди
оставшихся кандидатов. Все строки помечены как предварительные: нужны кривые,
Kv, минимальное давление, проверка среды/уплотнения и температурного режима.
GPS температурный предел и DN20 предел температуры остаются неизвестными.

Непривязанные аксессуары старых версий можно связать с конкретным теплообменником
через редактор строки; пересчёт создаёт только недостающие пары. Снятие привязки
оставляет автоматическое количество неизвестным, не NaN. Ручные количества,
выбор модели и цены сохраняются. Пример на синтетическом feed (не цены магазина):
нагреватель500 + насос100/200 + клапан300 увеличивают итог на900/1000/1000;
дешёвый DN50 за1 не выбирается при заданном G1. Повторный подбор не меняет сумму.

Проверки: 99 Django +11 Node; браузер — три источника, каталог/закрытие снаружи,
пары при qty2, выключение/восстановление, снятие привязки,0 JS ошибок.
Независимое ревью diff: блокеров нет. Миграций/production изменений нет.
