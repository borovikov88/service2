# Версия XML, загрузка и архив услуг

Продолжение этапа 1, 24.10.2026. Код продолжает существующий редактор и журнал
AvitoServicesFeedVersion. Данные привязаны к connection/account/organization.

## Граница подтверждения

При новой локальной публикации создаётся отдельная привязка к записи версии:
SHA-256 XML, аккаунт, организация, отпечатки неизменяемого и постоянного URL.
Неизменяемый URL отдаёт только снимок этой записи, с проверкой SHA-256;
поздняя публикация не меняет его содержимое. Выключенный, перенесённый или
перепривязанный источник делает URL недоступным. GET не пишет историю.

Канонический origin берётся только из серверной настройки
AVITO_SERVICES_PUBLIC_ORIGIN (по умолчанию https://service2.aqualine22.ru),
а не из заголовка Host. Допустим только HTTPS origin без query/fragment,
учётных данных и пути. Сырые URL отчёта не сохраняются: используются
backend-only SHA-256 из документированного feed_urls (строка или object.url).

Автоматический читатель отчёта вызывает correlate_report после проверки
авторизованного аккаунта, generation/lease и привязки подключения. Проверяются:
- полный отчёт и законченная загрузка;
- aware started_at строго позже created_at опубликованной версии;
- единственный точный отпечаток URL источника;
- полный уникальный набор пар Id/AvitoId;
- целостность снимка и привязка к текущей организации/аккаунту.

Если URL отчёта точно совпадает с неизменяемым URL и загрузка завершилась
success/success_warning, подтверждается обработка источника этой версии.
Ошибки и статусы каждого объявления показываются отдельно: наличие связи
с источником не означает активность всех строк или применение текста.
content_verified всегда false: этот контур не получает фактические тексты
и фотографии из используемого item-detail ответа для сравнения.

Если используется постоянный feed.xml, совпадение времени и идентификаторов
даёт только кандидатную связь. Другой/отсутствующий URL или несколько источников
не подтверждают версию. API Авито может указывать свою копию файла; это само
по себе не доказывает неверную настройку. При вращении подписанного URL копии
сохраняется обычная проверка согласованности отчёта, но точное подтверждение
источника снимается. Старый отчёт никогда не подтверждает новую публикацию.

Для сильной связи владелец указывает в настройках автозагрузки аккаунта адрес
неизменяемой версии с экрана Service2. При следующей публикации нужен новый
адрес. Настройки провайдера этим кодом автоматически не изменяются.
Сильная связь возможна только если API отчёта возвращает исходный адрес;
если возвращается только адрес копии Авито, подтверждение источника остаётся
ограничением провайдера/контракта.

История попыток уникальна по версии, upload_id и семантическому хешу отчёта.
Одинаковый повтор не создаёт дубль, переход processing → finished сохраняет
отдельные результаты. Старый отчёт может сопоставиться с прежней версией,
не переводя более новую версию из ожидания. Выбор последнего результата идёт
по началу загрузки, а не по времени позднего получения старого ответа.

## Архив и намерение владельца

Отдельная отметка owner_withdrawn — политика Service2 с автором, временем и
изменением до/после в журнале. Она не снимает объявление в Авито и не доказывает,
кто совершил действие на стороне провайдера. Снятие отметки не запускает
публикацию и не подтверждает её стоимость.

Различаются:
- явный запрет владельца возвращать объявление;
- removed: снято, инициатор API не передан;
- old без достаточного отчёта: архив, причина не подтверждена;
- old в item detail и отчёте с прошедшим provider avito_date_end:
  «Авито сообщает: срок размещения истёк» (намерение владельца не угадывается);
- rejected, blocked, active, неизвестный статус.

В доступном контуре API нет подтверждённого для текущего аккаунта метода,
который одновременно даёт нулевую дополнительную стоимость повторного
размещения услуги и выполняет его. ListingFee=Package и остаток денег не
подменяют эту проверку. DateEnd и срок +30 дней не вводятся предположительно.

Автоматическая активация заблокирована, стоимость неизвестна. Конкретный
ручной шаг: открыть существующее объявление в архиве Авито, проверить нулевую
доплату и повторно опубликовать его с сохранением идентификаторов, не создавая
копию. Для blocked/rejected сначала требуется указанное Авито исправление
или обращение в поддержку. Для removed сначала уточняется причина снятия.

После внешнего действия повторная проверка может подтвердить old → active
при тех же Id/AvitoId и новом finish_time, большем прежнего уже прошедшего
срока. Подтверждается наблюдаемый статус и новый срок, инициатор и стоимость
остаются неизвестными; Service2 не приписывает себе выполненную активацию.
Без нового известного срока показывается только active. Запрет владельца
автоматически не снимается.

## Проверки

Регрессии покрывают сильный и кандидатный источник, старый/равный/незаконченный
отчёт, смешанные URL, изменённые/повторные пары идентификаторов, ошибки строк,
неполную пагинацию, будущую дату, повторы, старую и новую версии, неизменность
XML и блокировку при смене аккаунта/повреждении снимка, приватность URL,
пометки владельца/CSRF/организации и подтверждение нового срока.

Локальная среда выполнения в сессии недоступна. Запуск тестов не заявляется
до штатного CI родительского PR и независимого review финального combined head.
