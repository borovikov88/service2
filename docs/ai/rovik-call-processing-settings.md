# Ровик: подготовка правил автообработки

Продолжение PR #278. Этот блок добавляет работающие сохранение настроек и бесплатный предпросмотр, но НЕ включает массовую авторасшифровку, скрытие действующего журнала или создание задач агентом.

## Интерфейс

`Коммуникации → Автообработка`, URL `/communications/calls/auto-processing/`. Доступ — текущий активный владелец своей организации; суперпользователь не получает обхода. Новый пункт навигации не меняет разрешения существующих разделов.

Для каждого действующего сотрудника сохраняются «Только вручную», «Все, кроме личных исключений» либо «Только по правилам». Разрешающий режим поддерживает сотрудников и список рабочих номеров. Правила другого владельца, включая рабочие номера, не показываются и не изменяются. При отсутствии настроек правило фактически ручное; никакой массовой записи настроек существующих сотрудников нет.

Личный список хранится отдельно, доступен только добавившему владельцу, поддерживает несколько номеров с одной подписью и нормализацию через действующие ключи CRM. Исключение действует лишь на звонки с участием этого владельца. Действующий журнал, аудио, экспорт, MCP и производные задачи этим блоком НЕ скрываются: это явно написано на странице и в сообщениях сохранения. Подготовленный список нельзя считать уже действующей защитой.

## Предпросмотр

Симуляция за 7 дней читает не более 501 записи метаданных, оценивает первые 500 и явно сообщает об ограничении выборки. Содержимое файлов, тексты расшифровок и резюме не возвращаются. Сохранённый текст проверяется только булевым SQL-выражением. Нет вызова платного провайдера, запросов на обработку или создания CallAnalysis.

Все установленные участники должны разрешать обработку. Неоднозначная/отсутствующая привязка к подтверждённой активной телефонной линии запрещает отбор. Приоритет: личное исключение → идентификация → правила участников → готовность записи. Неизвестный CRM-клиент сам по себе не препятствие. Готовый анализ не повторяется; при сохранённом тексте предлагается продолжение анализа, а не повторное распознавание.

Для внутренних звонков учитываются обе стороны и подтверждённые номера/учётные записи. Неизвестный телефон при имеющемся личном списке не считается разрешённым автоматически. Сопоставление пока консервативное: например, короткого внутреннего номера может быть недостаточно для проверки личных исключений. Личные строки полностью исключаются из ответа предпросмотра; счётчик содержит лишь исключения просматривающего владельца.

Количество и минуты относятся к записям в выборке, а не к подтверждённым платным попыткам или дедуплицированным физическим разговорам. Денежные суммы не выдумываются.

## Запись и безопасность

Миграция 0133 после 0132 создаёт только три пустые таблицы: правила, личные номера и журнал изменений настроек. Нет backfill, платных действий или изменений прежних звонков. Каждая запись настроек выполняется атомарно под блокировкой организации и повторной проверкой актуального владельца; правило дополнительно защищено ожидаемой revision. Журнал содержит режим и количества, но не копии личных телефонов/подписей. Ошибка журнала откатывает изменение настроек.

`effective_from` остаётся NULL: сохранение не активирует автоматизацию. Никакая готовность worker/приватности/бюджета не предполагается по наличию этих таблиц. Предпросмотр явно отключает только проверку исторической границы; при реальном policy-вызове отсутствие этой границы запрещает обработку.
