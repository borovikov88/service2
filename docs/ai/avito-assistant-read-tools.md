# Отдельное чтение Авито для ассистента

Ресурс: `https://service2.aqualine22.ru/mcp/avito`, OAuth scope `service2.avito.read`.
Защищённые метаданные: `/.well-known/oauth-protected-resource/mcp/avito`.
Используется существующий общий OAuth issuer и его authorize/token endpoints;
при deploy автоматически не создаются новый сервис, отдельный сборщик, клиенты,
grant или права пользователей. Отдельный grant создаётся только после явного OAuth-согласия.

## Доступ и границы

Нужно отдельное согласие на ресурс Авито. Прежние Finance, 1C Diagnostic и Operations
токены не подходят: проверяются точные audience, scope, активность токена/grant,
право principal на организацию и актуальные owner/admin + can_manage_channels.
Разрешение фиксирует организацию, подключение №4, аккаунт 446312402, канал и
поколение ключей. Смена привязки/ключей после показа согласия или выдачи токена
блокирует чтение. Сам по себе успешный вход в Service2 не выдаёт этот grant.
Товарное подключение №1 недоступно через данный ресурс.

Только чтение сохранённых данных. Инструменты не вызывают Avito API, не рассылают
сообщения и не меняют XML, публикации, тариф, продвижение, даты или CRM.
Клиент не передаёт URL провайдера, SQL, произвольный account_id или организации.
Методы записи/оплаты не объявлены в tools/list. Будущие записи требуют отдельного
scope, серверных полномочий и согласования конкретного действия/суммы.

## Инструменты

| Инструмент | Данные |
| --- | --- |
| get_avito_funds | Аванс CPA отдельно от денежных средств кошелька и бонусов |
| get_avito_listings | Сохранённые статусы, известные сроки и источник срока |
| get_avito_upload_report | Результат загрузки, коды/уровни сообщений и отдельные доказательства публикации |
| get_avito_statistics | Подтверждённые периодные снимки и независимая полнота суточной истории |
| get_avito_diagnostics | Компоненты фоновой проверки только этого подключения |

Все требуют `connection_id: 4`. Статистика дополнительно допускает пару
`date_from/date_to`, которая выбирает ровно сохранённый период и не запускает
новый запрос. Ответ содержит подключение, account, организацию, источник,
`served_at`, время получения каждого источника и полноту.
`served_at` не является временем получения данных Авито.

Пропуск поля/строки/даты не превращается в ноль. Время статистики обозначено
как даты источника, пока часовой пояс не подтверждён официально. Периодный итог
не создаёт суточные строки. Денежные поля имеют единицы; аванс, бонусы и кошелёк
не складываются. Отчёт обработки и source_version_confirmed не означают сверку
всего текста/фотографий карточки.

Старый кеш кошелька без проверяемой организационной/ключевой привязки не
усыновляется новым OAuth grant: возвращается cache_binding_unconfirmed без суммы.
Обычный защищённый refresh теперь сохраняет эту привязку для подключения №4.
Для аванса и подробного отчёта допустимо существующее подтверждение фоновой
привязки только при точном совпадении времени успешного снимка и обработчика.
Неудачное обновление не переименовывает прежний период или время.

## Диагностика выпуска и подключение

DB-only `pool_service.avito_mcp_reader.setup_evidence()` проверяет существующие
reader на сохранённых данных и выдаёт только имена инструментов, источники,
время, полноту и фиксированные коды. Она не создаёт OAuth токены/grant и не
подтверждает доставку инструмента в чат. Текущие рабочие суммы, тексты объявлений,
имена/сообщения клиентов и ответы провайдера в Git/логи не экспортируются.
Аудит MCP сохраняет только имя инструмента, организацию, исход, размер и время.

После штатного deploy нужно подключить отдельный ресурс `/mcp/avito` в настройках
инструментов ассистента и подтвердить на защищённой форме чтение Услуг №4.
Если публичный ChatGPT OAuth client/principal ещё не разрешён для организации,
уполномоченный администратор использует существующий процесс регистрации клиента;
данный выпуск не расширяет principal scope автоматически. Проверка DB reader,
OAuth regression tests и подключение реального чата — отдельные свидетельства.

Защищённый `pool_service.avito_mcp_setup.prepare_wallet_once()` при выпуске может
выполнить одно ограниченное чтение кошелька подключения №4. Он требует существующий
`SERVICE2_AVITO_DEPLOY_SETUP=1` gate штатной команды, общий workspace lease,
консервативный бюджет запросов и одноразовую отметку на проверенную привязку.
HTTP выполняется вне транзакций, до и после проверяется собственный account и
актуальные права/ключи. При ошибке старый payload/time сохраняются; повторный deploy
не повторяет уже предпринятую попытку. Receipt не содержит денежных значений.
Это подготовка проверяемого кеша, а не дополнительный сборщик или действие OAuth grant.
