# Входная копия Авито: дополнительное доказательство версии

Опциональное чтение копии продолжает существующий fetch_report. По умолчанию
include_input_proof=False: прежние и товарные вызовы не делают новых запросов.
Для включённого автоматического читателя услуг требуется прежний явный marker
avito_services_workplace_v1.automatic_reports_configured_once, действующие
аккаунт/организация/ключи/актор, разрешённая и включённая подписка и привязанный
источник услуг. Opt-out не переопределяется. Отдельного скрытого флага нет.

URL берётся только из единственного feed_urls аутентифицированного отчёта.
Разрешены HTTPS/443 и домены avito.ru, avito.st либо их dot-subdomains.
Используется существующий транспорт фото: только публичные DNS-ответы, числовой
IP закреплён до соединения, TLS проверяет исходный hostname. Нет redirects,
cookies, provider Authorization, декомпрессии или сохранения URL/XML.
Сеть выполняется вне транзакции корреляции. Ограничения: 8 секунд на копию,
4 MiB, 200 объявлений, 50000 XML-узлов, глубина20. DTD/entities запрещены.
ZIP-пакет XLSX определяется по структуре, не конвертируется в предполагаемый XML.

Весь XML должен иметь корень Ads formatVersion3/targetAvito.ru, уникальные пары
Id/AvitoId и точное совпадение с полным отчётом. Только затем SHA-256 исходных
байтов сохраняется backend-only вместе с привязкой отчёта/подключения.
После скачивания повторно сверяются scope и API summary. Недоступность,
неподдержанный формат, истечение бюджета или смена summary не уничтожают
успешно прочитанный отчёт; отдельное доказательство получает фиксированный код.

При input_copy_http_401 сервер копии отказал в доступе. Это отдельный результат
проверки входного файла, а не ошибка всех объявлений или самого подробного
отчёта. Bearer/cookies не пересылаются на URL копии: без подтверждённого
контракта доступа нельзя объявлять содержимое проверенным или обходить отказ.

Корреляция выбирает единственную подходящую публикацию с этим SHA, созданную
строго до начала загрузки. Несколько версий с одинаковыми байтами неоднозначны.
Старый отчёт не подтверждает новую публикацию. source_copy_confirmed означает
совпадение входного XML, не фактического текста/фотографий публичной карточки.
content_verified остаётся false. Реактивация и покупки не выполняются.

Legacy-файл без AvitoServicesPublication binding автоматически не превращается
в новую публикацию. Журнал не подделывается и время не переносится назад:
новая локальная публикация может подтверждаться только последующей загрузкой.
Даже успешная XML-копия старого отчёта сама по себе не закрывает этот пробел.

В read-only диагностике для привязанного источника услуг не проверяются чужие
товарные Id и физические остатки Shop XML. Сохраняются отдельные измерения
покрытия активных услуг. Товарное подключение сохраняет прежнюю диагностику.
Глобальный audit partial и состояние фонового worker — разные результаты.

Публичная receipt выводит лишь фиксированные state/code, формат и счётчики.
SHA, URL, query, содержимое XML и внутренние binding-поля не публикуются.
Тесты: SSRF/DNS/TLS/header/redirect/budget, XML/DTD/идентификаторы/формат,
opt-in/opt-out, повторная проверка scope, неоднозначность версий, старый отчёт,
сохранение подробного отчёта при отказе копии и раздельная диагностика услуг.


## Проверка следующего выпуска

HTTP 401 наблюдался при GET сервером Service2 без аутентификации к ссылке
feed_urls конкретного отчёта. Это доказывает отказ данного запроса, но не
устанавливает требуемый вид авторизации и не доказывает отсутствие API
скачивания у Авито. В доступных первичных материалах не подтверждён контракт
скачивания этой копии. Передача сохранённого Bearer/cookies на её хост не
реализуется без официального endpoint/domain/header/scopes contract.
Точечный поиск в официальном домене не дал первичного описания; сторонние
OpenAPI-копии не используются как разрешение передавать токен.

Конкретный запрос в поддержку API Авито: «Ответ GET
/autoload/v4/uploads/last_successful содержит feed_urls[].url; unauthenticated
server-side GET этой ссылки возвращает 401. Какой официальный способ скачать
входную копию через client_credentials: endpoint, разрешённый домен,
Authorization header и scopes/права? Возвращает ли он исходные байты файла?»
Владелец также может открыть/скачать файл конкретного отчёта в авторизованном
кабинете; это ручное действие не становится автоматическим API-подтверждением.

publication_release_check(connection, revision=15, check_http=True) — только
чтение для protected diagnostic pipeline. Возвращает ограниченные числа,
boolean-флаги, ID/время записи истории; не URL, SHA, текст, фотографии, наборы
Id/AvitoId или автора. Проверяет scope, неизменяемую запись, состав и лимит,
равенство текущего draft/published, затем точные HTTP-байты канонического
неизменяемого URL. Используется прежний ограниченный DNS-pinned TLS transport:
без credentials/cookies, redirects, декомпрессии, с прежними лимитами.
После HTTP повторно проверяются scope, актуальность снимков и целостность.
Успех HTTP доказывает доступность нашего URL, не загрузку Авито.
Проверка не заменяет проверки существующего publish flow и не разрешает запись.

В интерфейсе раздельно показаны пять фактов: локальная публикация файла,
найденная последующая загрузка, связь источника с версией, обработка строк
найденной загрузки и проверка фактической карточки. Последний факт остаётся
false. Наличие обработанных строк при неподтверждённом источнике не выдаётся
за обработку новой версии. Точный неизменяемый URL может различить одинаковые
байты нескольких версий; противоречие с проверенным SHA копии блокирует
подтверждение. Старый отчёт по-прежнему не подтверждает новую публикацию.

Порядок ручного источника: обычная согласованная публикация в Service2 после
штатных проверок → protected HTTP-check конкретного immutable URL и состава →
при необходимости согласованный выбор одного источника владельцем в Авито →
ожидание штатной завершённой загрузки после публикации → результаты строк.
Не добавлять параллельную копию фида, не вызывать force-upload и не менять
тексты, цены или фотографии ради проверки. Если отчёт снова отдаёт только
защищённую копию 401, immutable URL не снимает ограничение автоматически.

Legacy revision 15 не объявляется новой проверенной публикацией задним
числом. Проверять фактическую production-запись и результат выпуска нужно
отдельно; само наличие helper/tests этого не доказывает.

Неизменяемый адрес закрепляет весь снимок объявлений, а не одну карточку.
После его выбора следующая публикация Service2 не обновит этот источник без
отдельной смены URL в Авито. URL с capability остаётся в авторизованном UI:
в GitHub receipt/logs/artifacts не попадает. Для owner handoff достаточно
страницы Service2, опубликованной ревизии, ID истории и времени HTTP-проверки.
