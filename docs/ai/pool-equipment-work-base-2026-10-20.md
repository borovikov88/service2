# Общая база монтажа оборудования

Исходный main bd19e95. Подтверждён дефект шаблонов, а не чужая ручная цена:
в commit8810574f758c557bedbd78a627aee08d5d13c7ba (PR334, перенос работ
из Excel) add_works(fresh=True) задаёт70000 только economy. Та же база
сохранена в source_rate. Документация объясняет пустые Standard/Lux:
их исходные комплектные формулы зависели от прежнего оборудования и не были
перенесены как новые ставки. Исходная книга сейчас отсутствует в workspace;
повторная проверка её ячеек не заявляется. Происхождение действующего
программного дефолта подтверждено Git-историей и существующим тестом.

Пользователь уже утвердил одинаковые ставки работ для разных КП.
Существующая база70000 применяется к equipment_work/компл. во всех новых
КП. Общая повышенная ставка организации берётся из существующей памяти
по той же работе/единице, без миграции записей и без смешивания организаций.
Повышение, подтверждённое в одном КП, меняет именно выбранное КП и становится
общей базой будущих расчётов; скидка не снижает память.

Контроль без организационных повышений: новые суммы standard/premium
увеличиваются ровно на70000 каждая, economy не меняется. Количество общих
работ остаётся1, в том числе с тремя нагревателями.
Открытие/валидация/сохранение старой версии не подставляет новые цены.
Явный пересчёт может заполнить старую незаданную автоматическую цену, как
и прежняя функция заполнения дефолтов; ручные цена/ноль/очистка защищены.
Нет миграций, изменений production и записи новых ставок без подтверждения.

Это узкое исправление монтажа оборудования. Цена неизвестной работы не
выводится из цен оборудования, транспортные единицы «рейс»/«комплект»
не смешиваются. Утренний отчёт исправлен: повторный вопрос об общих ставках
удалён, геотекстиль и штукатурка рассмотрены отдельно.

проверяющий подтвердил источник в Git, точные дельты, общую память повышений,
изоляцию организаций/единиц и сохранность ручных значений/истории.
