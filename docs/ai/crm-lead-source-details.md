# Метаданные обращения в лидах: локальный пакет

База: main f65cea03c6f19f381b4514d7c3d1ea6fabfbafe4. Публикация не разрешена.

## Критерии и реализация

- Плашка показывает последний доступный источник, номер или имя контакта,
  время события (или явно подписанное время получения) и сотрудника звонка.
  Сотрудник звонка не подменяет ответственного за лид. Общий заголовок intake
  получает вычисляемую подпись; сохранённый title и ручные названия не меняются.
- Источники читаются пакетно и ограничены по количеству, через существующий
  scope/приватность crm_lead_access. В списки не попадают тело сообщения,
  запись, расшифровка или факты анализа. Неизвестные данные не угадываются.
- В деталях запись и готовая сохранённая расшифровка доступны только после
  существующей проверки права прослушивания. Запись использует прежний endpoint
  с явным org_id; тот теперь использует существующий _selected_access, сохраняя
  прежнее поведение без org_id. Отзыв права/личный номер проверяются повторно.
- Плеер имеет preload=none и не запускается автоматически. GET карточки не
  обращается к status endpoint, не создаёт анализ и не запускает worker.
  Запуск/повтор распознавания остаётся явным действием в существующих
  «Коммуникациях», по существующим правам и политике обработки.
- Из готовых facts показаны только ФИО, компания, телефон, адрес, потребность.
  Это предложения для проверки, а не подтверждённая идентичность. Только
  предложение потребности может быть явно подставлено в существующую форму.
  Оно не заменяет уже изменённый вручную текст и само ничего не сохраняет.
  Последующее сохранение проходит прежний revision/idempotency command service.
  ФИО/телефон не создают и не меняют Client автоматически.
- Текст источников/расшифровки выводится через textContent. Транскрипт ограничен
  20000 символами с явной пометкой об усечении и ссылкой на исходную коммуникацию.

## Проверки

Целевые Django-наборы: test_crm_lead_intake, test_crm_lead_views,
test_call_privacy_enforcement. Сценарии: нет права listen при доступном лиде;
отзыв права и личный номер; другая организация и двойной org_id; ready/pending;
неизвестный сотрудник/время; отсутствие мутаций и запуска анализа при повторном
GET; прежние scope/replay guards. Существующая проверка количества SQL-запросов
сохраняется.

Реальный Chromium: прежний канбан; новый звонок и сообщение Avito, неизвестное
время события, безопасный вывод текста с HTML, отсутствие автоматической загрузки
аудио и analysis requests, явное воспроизведение локальной синтетической WAV,
подстановка/защита ручного текста/явное сохранение/перезагрузка, 390px и dark.
Никакое реальное аудио или клиентские данные в тестах не используются.

## Границы

Нет миграций, изменений intake, дедупликации, маршрутизации, ролей, grants,
кохорт, расписаний или AI-провайдера. Исходящие звонки и email этот пакет не
добавляет в intake. Сценарий одной потребности через несколько обращений —
отдельная будущая задача. Production-данные и интерфейс здесь не проверялись.
Локальный Chromium и SQLite не заменяют обязательные MySQL/закреплённый Chromium
в CI перед возможным выпуском. Новый пакет пока только локальный.

## Локальная квитанция проверки

46 целевых Django-тестов и 7 Node-тестов прошли; check и отсутствие миграций —
PASS. Окончательный браузерный модуль завершился: 4 теста PASS (два реальных
Chromium-сценария и две проверки завершения/таймаута дочернего процесса).

Диагностика выявила timeout page.reload: тест ожидал только пустую очередь
операций, но applyResult очищает её до завершения loadList. Теперь перед reload
проверяются успешный GET обновления, aria-busy=false и сохранённое значение.
Все проверки данных, аудио, приватности и responsive сохранены.

Harness использует временные файлы для stdin/stdout/stderr и ограниченный wait.
При таймауте он останавливает только собственную группу процессов, созданную
через start_new_session, и ограничивает ожидание её завершения пятью секундами.
Нет безусловного ожидания Popen.__exit__. Отдельный тест подтверждает фактическое
завершение зависшего дочернего процесса. Privacy/production-код при этой
диагностике не менялся. Гипотеза о privacy-компиляции как первопричине не доказана.

Локально использован установленный Chromium154 и Python3.12. MySQL и закреплённый
CI Chromium остаются обязательными перед возможной публикацией/выкладкой.
Публикации, запуска распознавания и изменений production не было.
