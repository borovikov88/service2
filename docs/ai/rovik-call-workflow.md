# Ровик: разговоры, конфиденциальность, расходы и жизненный цикл задач

Решения владельца от 7 октября 2026. Это единая область работ в PR #278, не разрешение считать незавершённые пункты внедрёнными. Не создавать отдельные development-чаты Codex без согласования.

## Уже добавленный код в текущем продолжении

- Обсуждение CRM-задачи и явные действия: комментарий, перенос, ожидание с отдельной будущей проверкой, отмена, выполнение.
- Комментарий сам не меняет статус. Причина сохраняется в существующей истории, первоначальное описание не перезаписывается.
- Ожидание снимает старый срок встречи, но сохраняет дату внутренней проверки. Не называть эту дату обещанием клиента.
- Отмена не является выполнением. Выполнение использует существующий сервис архивации.
- Проверки организации/существующих прав, единый task/CRM lock order, защита от устаревшей формы и повторной отправки, атомарная запись истории.
- Контроль различает дедлайн и внутреннюю проверку. Старый отложенный control-push повторно проверяет актуальное состояние перед отправкой.
- События сохранены в ServiceTaskChange с schema=service2.task-feedback.v1 и revision. Передача/ack Ровику пока НЕ подключены; UI честно об этом сообщает.
- Новые таблицы/миграции и изменения production-данных этим блоком не выполняются.

## Обязательные оставшиеся блоки (НЕ реализовано только наличием этой записи)

### Автообработка

Одна страница «Коммуникации / Звонки / Автообработка». Для выбранных действующих рабочих линий сотрудников: все входящие/исходящие разговоры, включая неизвестных клиентов. Новые/несопоставленные линии по умолчанию выключены. Для владельца сейчас: сотрудники + разрешённые рабочие номера. Поддержать переключение на «все, кроме личных», но не включать его за владельца. Правила на новые записи после effective_from; старый архив только отдельным подтверждённым запуском. Перед включением — предпросмотр на неделе без платных запросов.

Расшифровка начинается после успешного получения пригодного аудиофайла, а не после появления метаданных звонка. Повторно сверить политику перед отправкой и перед публикацией результата. Существующую сохранённую расшифровку не распознавать повторно. Идемпотентность и восстановление очереди после сбоя обязательны.

### Личные контакты

Личный список владельца доступен только ему; применяется к его разговорам, а не глобально к любому рабочему звонку того же контакта. Исключение сильнее разрешений второго сотрудника. Учитывать нормализацию телефона, несколько номеров, оба участника/переадресации. Не определять «личное» отправкой аудио на ИИ-анализ.

Запрещённые записи не выдавать в рабочем журнале, поиске, экспорте, по прямым URL, через MCP/агента, резюме/задачи/уведомления. Для новых разговоров отсеивать до скачивания аудио, где возможно. Скрытие DOM не защита. У старых записей ограничить дальнейший доступ и отдельно согласовать удаление: не удалять автоматически ни аудио, ни задачи. Скрытие не означает, что копия в Мегафоне удалена или ранее переданное ИИ забыто.

### Расходы

Отдельный ledger стадий/попыток/моделей, уникальные минуты и фактическая обработка, разрезы сотрудник/день/месяц. Оценка по версии тарифа и подтверждённое списание различаются; неизвестное не подменять нулём. Не суммировать расходы DOT и API без данных. Конкурентное резервирование бюджета до вызова, ограниченные retries, пауза по лимиту; попытки/таймауты могут стоить денег. Не использовать реальные личные данные в Git/тестах.

### Единый создатель задач

Ровик инициирует создание задач через Service2; встроенное materialize_call_commitments в новом режиме готовит предложения вместо параллельного создания/рассылки. Старые задачи не пересоздаются. Для внутренних разговоров: created_by_agent=Ровик, поручение дал=подтверждённый участник, исполняет=подтверждённый сотрудник. Не назначать всё владельцу линии и не угадывать личность спикера. Неясные поручения/исполнители/сроки требуют уточнения.

Идемпотентный ключ должен ссылаться на звонок/конкретную договорённость, не только на произвольный текст от модели. Повторный анализ, обе стороны одного звонка и повторная доставка не создают дубликаты. Новые подтверждённые человеческие изменения сильнее старой расшифровки; устаревший ответ агента не может восстановить отменённую встречу.

### Очередь для Ровика

Расширить Operations MCP готовыми новыми разговорами, предложениями и событиями задач, включая завершённые/отменённые. Постраничный устойчивый cursor, версия записи, audit, идемпотентные ack только реально просмотренной версии; читать только разрешённые данные нужной организации. Сначала предложения на согласовании. Наличие requires_review в payload НЕ означает, что DOT читает очередь. Нужен реальный подключённый и проверенный consumer/цикл DOT; не обещать немедленный запуск без проверки.

Добавить операции обсуждения, ожидания, отмены, просмотра истории и подтверждения обработки с optimistic concurrency. Обновление карточки человеком должно само отключать неактуальные напоминания, даже если DOT недоступен. Связанные задачи менять только по явной связи и подтверждённому охвату.

Авторизация и включение рабочего MCP должны быть подтверждены отдельно; никогда не писать «Ровик подключён» только по факту merge.
