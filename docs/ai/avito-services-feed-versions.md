# Источник объявлений услуг: версии и контроль публикации

Продолжается существующий AvitoServicesFeed; новый контур интеграции не создаётся.
Первое эксплуатационное подключение — услуги. Код изолирует каждое подключение,
аккаунт и организацию; никаких автоматических действий с другими подключениями нет.

## Критерии этого выпуска

1. Если из 11 известных объявлений одно стало неактивным,10 подтверждённых
   активных можно публиковать без повторной отправки неактивного. Все 11 остаются
   в черновике и истории. Любое отсутствующее активное объявление блокирует файл.
2. Принадлежность подтверждается существующим API аккаунта и деталей каждого
   объявления. Неизвестный статус, чужое/недоступное объявление, противоречие
   списка и деталей, изменение Id, пропущенная известная строка или гонка
   revision/account/organization блокируют действие.
3. Импорт, редактирование и новый опубликованный XML принимают максимум 10
   фотографий. Прежний опубликованный файл с 11–30 изображениями продолжает
   выдаваться без усечения; после следующей публикации лимит файла становится 10.
4. Черновики, локальные публикации и чтение статусов сохраняются как отдельные
   события с автором, временем, причиной, полями до/после и приватным снимком.
   Восстановление создаёт новый черновик и требует новой публикации.
5. В интерфейсе нет утверждения о применении текста/фото на Авито без доступного
   провайдерского доказательства. Известный срок хранится с источником; отсутствие
   срока остаётся null, не нулём и не предположением «через 30 дней».

## Архив и активный состав

Проверка читает полный активный состав аккаунта и детали каждой строки черновика.
В новой опубликованной версии остаются только подтверждённые active. old, removed,
rejected и blocked не отправляются повторно; соответствующие строки сохраняются
в черновике, журнале и списке исключений. old отображается как архив с
неподтверждённой причиной. Один этот код не доказывает штатное истечение срока.
Неизвестный статус блокирует публикацию.

Защита полного состава активных объявлений сохраняется. Дополнительно проверяется
биекция Id↔AvitoId во всех накопленных снимках. Импорт, пропустивший любую известную
строку (например, свежий экспорт только активных без архивного объявления),
отклоняется. Редактировать сохранённый полный черновик можно; автоматического
удаления старых идентификаторов, объединения чужих выгрузок или создания копий нет.

Новая версия сохраняет прежние идентификаторы всех включённых объявлений. При
отсутствии активных строк пустой файл не публикуется: последний опубликованный
снимок сохраняется.

Проверка ограничена 45 секундами плюс тайм-аут последнего запроса; часть результата
не используется как успешный состав. Более старое завершившееся наблюдение не
перезаписывает новое. GET страницы и публичного XML не вызывает Авито и не пишет БД.

## История

Аддитивная миграция 0144 создаёт AvitoServicesFeedVersion и поля последней успешной
проверки/совместимости. В production не выполняется догадочный backfill. При первом
следующем действии старый черновик и прежняя публикация сохраняются как baseline:
время и автор прежнего изменения не восстанавливаются и не приписываются текущему
пользователю.

Приложение добавляет события, но не изменяет существующие. Прямое сохранение уже
существующей модели отклоняется. Это приложение с журналом, а не криптографическая
или административная защита БД от прямого SQL. Журнал находится в БД и не выводится
в Git/публичные логи.

Для локального файла сохраняются точный SHA-256 XML и ссылка на исходную запись
черновика. Статусная проверка может ссылаться на последнюю локальную публикацию;
это контекст проверки, а не доказательство приёма именно этого файла Авито.
История показывается по 20 записей на страницу, сохранённые записи не обрезаются.
Сравнение показывает поля до/после с обычным HTML-экранированием.

Восстановление снимка сохраняет объявления, добавленные позднее. Восстановление
прежнего опубликованного подмножества не удаляет исключённые архивные строки.
Смена состава и идентичности без проверки не разрешена. Операции защищены CSRF,
capability, свежей привязкой аккаунта/организации и блокировкой connection/feed.

## Доказательства и ограничения

Сохранение черновика, публикация XML по ссылке, обработка файла Авито, модерация и
применение — разные этапы. В этом выпуске есть первые два и отдельное чтение
текущего статуса/известного finish_time через существующий метод деталей Авито.

Данные finish_time сохраняются только как корректное время с часовым поясом,
источник — avito_item_detail.finish_time. Не переданное/неподдерживаемое значение
остаётся неизвестным. Это срок объявления, не срок тарифа. Проверка не делает
предположения о дополнительной стоимости.

Провайдерский метод деталей не возвращает содержание Title/Description/Images.
Поэтому активный статус не обозначает подтверждённое применение редактирования.
Полная цепочка «версия файла → конкретная загрузка → результат строки» пока не
реализована. Проверка отчёта/свежести и точное подтверждение источника требуют
следующего выпуска. Ошибка API сохраняет прежнее успешное наблюдение с прежней
датой и показывает ошибку отдельно; источник не меняется.

Состав проверен на момент локальной публикации. Между этой проверкой и очередным
забором файла Авито объявление может истечь. Этот выпуск не управляет поведением
повторной автозагрузки и не гарантирует, что провайдер не активирует сохранённую
ранее строку самостоятельно. Для автоматической политики нужны подтверждённые
правила/тариф и контроль результата Авито. Публичный GET не меняет состав файла
скрыто: иначе сохранённый SHA и версия перестали бы описывать выдаваемый XML.

Бесплатная повторная активация, создание нового объявления, ручное снятие,
покупка продвижения, загрузка фотографий и проверка содержимого URL в этом выпуске
не выполняются. При неизвестной стоимости возвращение из архива требует ручной
проверки условий в Авито. ListingFee=Package не считается доказательством нулевой
дополнительной цены. Платных проверочных действий нет.

## Проверки

Целевые regression/security tests:
python manage.py test pool_service.tests.test_avito_services_feed
pool_service.tests.test_avito_services_feed_versions --settings=service_site.test_settings
Затем check, makemigrations --check --dry-run и штатный полный CI.

Рабочая среда исполнителя недоступна; локальные команды не запускались.
Результат CI, независимого review, merge/deploy и production-проверки фиксируется
в PR/операторском отчёте после выполнения. Наличие кода не означает включение
или успешное применение реальных объявлений.
