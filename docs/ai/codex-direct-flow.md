# Прямой цикл задачи из Codex-чата

## Выбранный способ оплаты и работы

Владелец подтвердил: разработка и независимое ревью используют Codex с
авторизацией ChatGPT и кредитами/лимитами тарифного плана. Отдельный OpenAI API
для этих задач не используется. Тарифные кредиты не являются балансом API.
При исчерпании лимитов автоматического перехода на API нет.

Ведущий принимает задачу, отдельный разработчик выполняет её, отдельный
проверяющий проверяет фактический diff по AGENTS.md. Замечания исправляются
в активной Codex-сессии. GitHub CI выполняет механические проверки и тесты.

## Штатное ревью GitHub

Используется Codex Code review для подключённого borovikov88/service2.
Настройка находится в Codex → Settings → Code review → Automatic reviews.
Документация описывает ревью новых PR и команду `@codex review` в комментарии PR.
Она также описывает запрос исправления через `@codex fix ...`.
Это возможности штатной интеграции, не наш Python-клиент OpenAI API.

В этой задаче отправлен реальный `@codex review` в PR №92:
https://github.com/borovikov88/service2/pull/92#issuecomment-5555556462
Бот `chatgpt-codex-connector[bot]` подтвердил запуск для head `b0ea2e4`:
https://github.com/borovikov88/service2/pull/92#issuecomment-5555557760
Проверка завершена: Codex сообщил об отсутствии серьёзных замечаний на том же
head. Результат: https://github.com/borovikov88/service2/pull/92#issuecomment-5555569709
Это подтверждает фактическое штатное ревью. Конкретное списание кредитов,
формальный GitHub APPROVED и полный цикл deployment этим не установлены.

## Вывод отдельного API-пути из эксплуатации

`direct-pr-review.yml` и `development-codex.yml` больше не должны выполнять
модельные запросы или публикацию через отдельный API-путь. Их оставленные
ручные точки входа сообщают о прекращении работы и завершаются ошибкой,
а не выдают отключённый reviewer за успешный check.
CLI `review_direct_pr.py` также блокирует старые команды до сетевых операций.
Общий клиент серверных development analysis/review отказывает в создании
OpenAI API-клиента даже при наличии ключа. Старые функции сохраняются только
для совместимости и проверок; это не реализованный переход серверного poller
на авторизацию ChatGPT. Серверная публикация сохранённых legacy-решений также
блокируется до чтения задачи и GitHub-запросов: старое accepted-ревью не должно
создавать APPROVED или включать auto-merge после отключения API-клиента.

Существующие canary-workflow с авторизацией ChatGPT сохранены. Их наличие не
доказывает доступность self-hosted runner или готовность полного серверного
DevelopmentTask-цикла. Сообщение Codex-чата не создаёт такую карточку автоматически.
Изменения Python-кода начнут действовать на hosting только после отдельного
deployment; production в этой задаче не обновляется.

## Границы автоматизации

Штатный Codex может публиковать замечания либо реакцию об отсутствии замечаний.
Ни 👍, ни комментарий, ни зелёный CI не преобразуются в GitHub `APPROVED`.
Существующий deploy gate с независимым approval актуального head сохраняется.
При отсутствии требуемого evidence deployment остаётся заблокированным.
Перед автоматическим merge нужно отдельно подтвердить актуальность ревью после
изменения head, base и исходной задачи; старый результат нельзя использовать.

Фоновый автоматический возврат замечаний разработчику, auto-merge и первый
production deploy пока не подтверждены. Не обещать их как следствие одного
включённого переключателя Code review. Финансовый MCP к реальным данным в этой
задаче не подключается. Секреты, тариф и платёжные настройки не изменяются.

## Проверка входа автоматизации через ChatGPT workspace

Штатное GitHub-ревью Codex уже работает, но не выдаёт необходимый `APPROVED`.
Для следующего независимого проверяющего сначала проверяется официальный вход
Codex CLI через `CODEX_ACCESS_TOKEN`. Это credential ChatGPT workspace, а не
Platform API key. Способ документирован для Business/Enterprise; конкретный
workspace владельца ещё должен разрешать создание токена и локальный Codex.
Переход на другой тариф или отдельный API автоматически не выполняется.

Подготовленный `codex-plan-connection.yml` запускается только вручную владельцем
из `main`. Он использует временный Linux runner, закреплённую версию CLI и
контрольную сумму архива. Из environment `review` передаётся только секрет
`CODEX_PLAN_ACCESS_TOKEN`, доступный процессу как `CODEX_ACCESS_TOKEN`.
Токен GitHub-проверяющего и SSH secrets этому процессу не выдаются.
Создание секрета не запускает workflow автоматически.

Один фиксированный тестовый запрос выполняется в пустом временном каталоге.
API credentials и переопределения провайдера запрещены, окружение дочернего
процесса ограничено, авторизация хранится в памяти без fallback на сохранённые
credentials. Конфигурация пользователя и правила не загружаются в этот пустой
тестовый контекст. Командные инструменты и внешние интеграции отключены;
операции записи ограничены read-only sandbox. Попытка использования инструмента
делает результат проверки неуспешным. Файлы PR и приложения не передаются модели;
пустой рабочий каталог сам по себе не является запретом чтения всего runner.
Вывод CLI и ошибки не публикуются; проверяется фиксированный ответ и числовая
статистика завершённого запроса. Проверка не является финансовым отчётом.

Порядок запуска после проверки кода:

1. Владелец проверяет доступность Access tokens в настройках ChatGPT workspace.
   Если доступ запрещён, сначала выясняется фактическое ограничение аккаунта;
   не предлагается пополнять Platform API или копировать browser cookies/auth.json.
2. Если доступ есть, создаётся ограниченный по сроку токен со scope Codex,
   затем сохраняется в GitHub Environment `review` как `CODEX_PLAN_ACCESS_TOKEN`.
   Значение токена не пересылается в чат. Требуемая в диалоге версия CLI должна
   быть совместима с закреплённой в workflow; несовместимость требует обновления
   кода и повторной проверки, а не автоматической установки latest.
3. Запускается `Check Codex plan connection` из `main` и проверяется результат.
   Отсутствие секрета, ошибка входа, timeout или неожиданный ответ означают отказ;
   запасного API-пути нет.

Успех доказывает вызов Codex этим runner через переданный workspace token.
Он не доказывает конкретную запись в платёжном журнале, формальное ревью PR,
автоматический merge или deployment. После успешного подключения отдельно
реализуется структурированный результат независимого ревью с проверкой точных
head/base/задачи и отдельной публикацией GitHub approval. Допуск к deployment
в этом canary не меняется. Старые API workflow остаются выведенными из эксплуатации.
