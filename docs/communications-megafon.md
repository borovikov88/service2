# МегаФон ВАТС ↔ Service2

Интеграция двусторонняя. В кабинете МегаФона показаны две разные пары полей, и их нельзя путать.

## Направление 1: Service2 → АТС МегаФона

В кабинете МегаФона есть неизменяемые поля:
- **Адрес АТС** — например `https://aqualine22.megapbx.ru/crmapi/v1`;
- **Ключ для авторизации в АТС**.

Их нужно **скопировать из МегаФона в Service2**. Они нужны, когда Service2 сам обращается к API АТС: например, для исходящего звонка из CRM, чтения данных телефонии или других API-команд.

В Service2:
1. Откройте **Коммуникации → Каналы связи → МегаФон**.
2. Нажмите **Адрес и ключ АТС**.
3. Вставьте скопированные из МегаФона **Адрес АТС** и **Ключ для авторизации в АТС**.
4. Ключ сохраняется только в зашифрованном виде.

## Направление 2: АТС МегаФона → Service2

В кабинете МегаФона есть редактируемые поля:
- **Адрес вашей CRM**;
- **Ключ для авторизации в вашей CRM**.

Эти значения, наоборот, выдаёт Service2.

В Service2:
1. На карточке линии нажмите **Данные для МегаФона**.
2. Service2 один раз покажет:
   - **Адрес вашей CRM** — HTTPS webhook Service2;
   - **Ключ для авторизации в вашей CRM**.
3. Вставьте их в соответствующие редактируемые поля кабинета МегаФона.
4. Для нужных номеров включите команды `history`, `event` и `contact`.

Повторное получение данных для МегаФона ротирует CRM-ключ. Старый ключ перестаёт работать.

## Что Service2 принимает от ВАТС

ВАТС отправляет webhook как `application/x-www-form-urlencoded`; Service2 также принимает JSON для тестов и совместимости.

Для команды `event` поддерживаются типы `INCOMING`, `ACCEPTED`, `COMPLETED`, `CANCELLED`, `OUTGOING`, `TRANSFERRED`. Для диагностики сохраняются `user`, `ext`, направление и номер клиента.

Для команды `history` Service2 принимает:
- `callid` — внешний идентификатор звонка;
- `type` — `in` / `out`;
- `user`, `ext` — данные сотрудника ВАТС;
- `phone` — номер клиента;
- `start` — начало звонка;
- `duration` — длительность в секундах;
- `status` — результат;
- `link` — HTTPS-ссылка на запись;
- `crm_token` — ключ авторизации нашей CRM.

Повторная доставка того же `callid` обновляет существующий звонок и не создаёт дубль.

Если `start` приходит без часового пояса, Service2 трактует его в `COMMUNICATION_TIME_ZONE`. Значения с суффиксом `Z` трактуются как UTC.

## Внутренние звонки между сотрудниками

Service2 отдельно забирает внутреннюю историю ВАТС через API
`/crmapi/v1/history/inner/json`. Используется уже сохранённый «Адрес АТС»
и тот же ключ авторизации в АТС — дополнительных секретов не требуется.

Синхронизация запускается вместе с `sync_call_recordings` и:
- забирает внутренние разговоры скользящими окнами;
- хранит один разговор одной записью по `uid` (`inner:<uid>`), без дубля входящий/исходящий;
- сохраняет обоих участников: кто звонил и кому звонил;
- показывает направление «Внутренний»;
- не пытается считать второго сотрудника CRM-клиентом;
- скачивает запись разговора с `X-API-KEY`, если ВАТС передала `record`;
- повторный проход обновляет ту же запись, а не создаёт новую;
- сотрудник с правом просмотра своих звонков видит внутренний разговор,
  если он является любым из двух участников.

На странице «Звонки» внутренние разговоры можно выбрать отдельным фильтром
«Направление → Внутренние». Фильтр по сотруднику учитывает обе стороны разговора.

## Автоматическое хранение записей

После команды `history`, если МегаФон передал `link`, Service2 автоматически пытается скачать MP3 в приватное хранилище приложения. Пользователю не нужно нажимать «Скачать».

- успешная запись хранится в `PRIVATE_MEDIA_ROOT` и воспроизводится встроенным плеером Service2;
- исходная ссылка МегаФона остаётся только как технический источник и не используется плеером после сохранения;
- временные ошибки помечаются для повторной загрузки;
- команда `sync_call_recordings` повторяет незавершённые загрузки;
- production workflow запускает повторную синхронизацию каждые 15 минут;
- HTML-страницы авторизации и другой неожиданный контент не сохраняются как аудио;
- максимальный размер файла задаётся `COMMUNICATION_RECORDING_MAX_BYTES`.

Если МегаФон перестанет отдавать сам файл по `history.link` и вместо MP3 вернёт страницу авторизации, Service2 оставит запись в состоянии ошибки. В таком случае нужно подключить официальный архив ВАТС через FTPS, а не ослаблять проверку контента.

## Безопасность

- Ключ авторизации **в АТС** хранится в Service2 зашифрованно.
- Ключ авторизации **в нашей CRM** хранится только как парольный хеш.
- Webhook принимает только активную линию и активное подключение организации.
- Записи открываются пользователю только через существующие права Service2.
- Скачивание записи разрешено только с доверенных HTTPS-хостов МегаФона; редиректы проверяются повторно.
- Локальные файлы записей не имеют публичного URL и отдаются только через авторизованный endpoint Service2.
- Запросы ограничены по частоте и размеру.

## Проверка

После настройки обеих сторон:
1. Сделайте входящий звонок.
2. Проверьте live-событие на карточке линии.
3. Завершите разговор и убедитесь, что появился `history`.
4. Откройте **Коммуникации → Звонки** и проверьте клиента, сотрудника, длительность и запись.
5. Повторите для исходящего звонка.
