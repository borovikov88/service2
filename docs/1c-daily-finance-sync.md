# Ежедневное обновление финансов из 1С

Один auto-apply run получает валовую прибыль, ДДС и начисленный ФОТ. Кнопка
«Обновить всё из 1С» запускает тот же механизм, что и серверный worker.
Права на импорт всех трёх отчётов и действующий доступ к организации обязательны.
Проверка GET не запускает импорт. В 1С выполняется только чтение.

## Период и применение

По умолчанию обновляются текущий и два предыдущих месяца: это окно включает
поздние изменения. Более старые исправления можно получить ручным запуском
с явным периодом, максимум 24 месяца. Ежедневное окно задаётся
`ONEC_FINANCE_LOOKBACK_MONTHS` (1–24). ФОТ — начисления, не выплаты или остатки.

Сначала собираются и проверяются все три источника. Активация выполняется
совместно в транзакции существующего auto-apply механизма. Ошибка источника,
потеря прав, изменение конфигурации/активной версии или повреждение snapshot
не разрешают применение подготовленных изменений. Предпросмотры и история
не удаляются. Повтор с неизменными данными не создаёт повторных начислений.

Пустой ответ ФОТ не считается нулём: прежний ФОТ месяца сохраняется, а
пропущенный месяц отмечается в результате. Он может означать ещё не проведённую
зарплату или отмену данных — это требует внимания оператора. Нельзя представлять
такой месяц как свежий подтверждённый нулевой ФОТ.

Автоматическое принятие охвата ФОТ включается отдельно: значение
`ONEC_ODATA_PAYROLL_AUTO_COVERAGE_GUIDS` должно точно соответствовать проверенному
набору `ONEC_ODATA_ORGANIZATION_GUIDS`. Администратор принимает, что часть этих
организаций может не иметь строк в месяце; отсутствие строк не доказывает ноль.
Изменение списка источников требует нового явного согласования. Валюта и сверка
двух регистров остаются обязательными. Никакие рабочие GUID в Git не сохраняются.

## Включение на проверенном хостинге

Код не устанавливает cron и не включает расписание при deployment.
До включения проверить точный deployed HEAD, миграции и успешный ручной запуск.
В существующем `.env` задать (не добавлять повторные строки):

```dotenv
ONEC_FINANCE_DAILY_ENABLED=false
ONEC_FINANCE_SYNC_USER_ID=<ID действующего пользователя service2>
ONEC_FINANCE_DAILY_TIME=06:00
ONEC_FINANCE_TIME_ZONE=Asia/Barnaul
ONEC_FINANCE_LOOKBACK_MONTHS=3
ONEC_ODATA_PAYROLL_AUTO_COVERAGE_GUIDS=<проверенный набор организаций источника>
```

Это ID пользователя приложения, а не GitHub/Codex, не GUID 1С. Его текущие права
на все отчёты проверяются при каждом выполнении. Worker продолжает ручную задачу
от имени её исходного инициатора, не повышает права за счёт пользователя cron.
OpenAI API, Codex token и дополнительные секреты для импорта не нужны.

В каталоге production checkout выполнить:

```bash
../venv/bin/python -B manage.py sync_onec_finance --check
```

`--check` выполняет только проверку настроек и SELECT прав, не обращается к 1С,
не создаёт запусков, не меняет данные или расписание. `CONFIG_OK` не означает,
что cron установлен либо реальный импорт завершён. Значения credentials не
выводятся. После проверки включить `ONEC_FINANCE_DAILY_ENABLED=true` и штатно
перезапустить Passenger, чтобы веб-процесс увидел настройки.

В Beget → CronTab → «Произвольная команда» добавить **одну** запись с интервалом
каждую минуту (`* * * * *`). Существующие задания не удалять и не заменять.
Команда с проверенным путём этой установки:

```bash
cd /home/b/borovidz/service2.aqualine22.ru/service_site && ../venv/bin/python -B manage.py sync_onec_finance --max-steps 4 --max-seconds 240
```

Каждую минуту запускается лишь обработчик очереди, не полная выгрузка. Он создаёт
не более одной плановой попытки на локальную дату после 06:00 по Барнаулу,
а существующую ручную/плановую задачу продолжает по её cursor. Сбой плановой
попытки не создаёт бесконечные новые запуски в этот день. Ручной запуск разрешён
после завершения/ошибки предыдущего. Если пользователь закрыл браузер, cron
продолжит оставшиеся шаги. Без установленного cron такого обещания нет.

При занятом lease worker выходит без повторного запроса. Общая граница времени
процесса — 240 секунд; незавершённый шаг разрешено повторить после истечения
lease (300 секунд). Команда возвращает ненулевой код при таком прерывании;
результат нельзя считать успешным. Промежуточные активные данные не применяются.
Повторяемая ошибка чтения ВП/ДДС откладывает следующую фоновую попытку на 15 минут;
ошибка проверки ФОТ безопасно останавливает весь запуск до нового запуска.
Браузерный
оператор может повторить вручную. Автоматический запуск чужой preview-задачи
запрещён — её необходимо завершить отдельно.

После добавления cron проверить фактический вывод первого tick и результат
в истории приложения. Только успешный результат всех источников подтверждает
обновление; вызов cron, HTTP 200 или зелёный CI этого не доказывает.

Отключение ежедневного создания: `ONEC_FINANCE_DAILY_ENABLED=false`. Уже принятые
ручные/плановые auto-apply задачи worker продолжает. Чтобы остановить и очередь,
отключить конкретную cron-запись; уже выполняющийся процесс этим не прерывается.
Перед повторным включением проверить историю, права и актуальные настройки.

Beget поддерживает настройку и пробный запуск произвольной cron-команды через
мобильный браузер: https://beget.com/ru/kb/manual/crontab .
