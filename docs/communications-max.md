# Переписка через MAX

1. В MAX API вызовите `GET /me` для нужного бота. Сверьте его публичное имя и
   возьмите числовой `user_id`.
2. В нужной организации «Ровика» откройте «Коммуникации» → «Каналы связи» → MAX.
   Создайте подключение с этим `user_id`. Сохраните HTTPS-адрес и выданный
   секрет вебхука в защищённом месте.
3. Проверьте действующие подписки бота через `GET /subscriptions`. Для
   подключения отправьте `POST /subscriptions` с выданными `url`, `secret`
   и `update_types: ["message_created"]`. Токен бота передаётся в заголовке
   `Authorization` только при обращении к официальному API MAX. Токен бота
   и секрет вебхука — разные значения. Сервис хранит только хеш секрета
   вебхука. Убедитесь, что в ответе `success: true`, и заново проверьте
   адрес и тип события через `GET /subscriptions`.
4. После регистрации отправьте новое сообщение боту в личном диалоге.
   Проверьте «Коммуникации» → «Диалоги» в организации подключения. При
   включённой обработке входящих CRM создаст лид или подберёт открытый.

Вебхук принимает личные диалоги и проверяет заголовок
`X-Max-Bot-Api-Secret`. Повторная доставка того же сообщения не создаёт
дубликат.

## Ответы менеджеров

В настройках существующего подключения MAX заполните поле «Токен бота MAX»
токеном из кабинета MAX. «Ровик» сверяет его с идентификатором бота через
`GET /me` и при совпадении сохраняет токен зашифрованным. Секрет вебхука и
подписка доставки входящих остаются действительны.

В личных диалогах MAX сотрудники с правом отвечать могут отправлять текст
до 4000 символов. Ответ отправляется через `POST /messages` по идентификатору
участника диалога. Повтор одной отправки из формы не создаёт дубль.
Если MAX не подтвердил отправку, проверьте диалог в MAX, прежде чем писать
повторно.

## Вложения и телефон

Сотрудник может приложить одно фото, видео, аудио или файл до 10 МБ к ответу.
Входящие фото, видео, голосовые, файлы и стикеры открываются из диалога.
При первом открытии «Ровик» получает свежую ссылку через API MAX и сохраняет
вложение до 25 МБ в закрытом хранилище. Доступ к просмотру и скачиванию
ограничен правом на диалоги организации. Несохранённое вложение доступно,
пока MAX может вернуть его. Если у вложения нет идентификатора MAX и
подписанный адрес изменился, «Ровик» не сможет подтвердить, что это тот же
файл. События, сохранённые до этой версии только как отметка о вложении,
остаются в истории.

В диалоге нажмите «Запросить телефон». В MAX клиент получит кнопку «Поделиться
телефоном». После добровольной отправки проверенный номер появится в том
же диалоге. Он не копируется в общую карточку клиента или пуш-уведомление.
«Ровик» проверяет сигнатуру MAX и совпадение идентификатора участника,
когда MAX передал его в карточке контакта. Полный vCard не сохраняется.
Неподтверждённый контакт отображается как вложение.

## TLS для API MAX

Для HTTPS-соединений с `platform-api2.max.ru` клиент MAX добавляет
[корневой сертификат Минцифры](https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt)
в собственный контекст TLS. Проверка цепочки и имени хоста обязательна.
Отпечаток SHA-256 корневого сертификата
`d26d2d0231b7c39f92cc738512ba54103519e4405d68b5bd703e9788ca8ecf31`.
