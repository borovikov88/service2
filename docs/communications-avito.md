# Подключение Авито к коммуникациям

Интеграция работает отдельно для каждого `ChannelConnection`, поэтому одна
организация может подключить несколько аккаунтов Авито. В `external_id`
подключения указывается числовой ID аккаунта Авито.

## Настройка

Основной путь настройки — интерфейс Service2:

1. Откройте **Коммуникации → Каналы связи → Авито → Добавить подключение**.
2. Укажите название подключения, числовой ID аккаунта Авито, `client_id` и
   `client_secret`. Секреты не отображаются после сохранения и хранятся только
   в зашифрованном виде.
3. После сохранения нажмите **Подключить Авито**. Service2 сам получает
   access token по `client_credentials`, создаёт новый секретный webhook URL,
   регистрирует его через `POST /messenger/v3/webhook` и подтверждает наличие
   подписки через `POST /messenger/v1/subscriptions`.
4. Кнопка **Проверить** повторно сверяет активные подписки Авито с текущим
   webhook-токеном Service2. **Переподключить Авито** создаёт новый токен,
   регистрирует новый URL и после подтверждения удаляет старые подписки Service2
   для этого подключения.

Webhook-токен не показывается пользователю и не хранится в открытом виде:
Service2 хранит только его хеш. Секретная часть URL появляется только в памяти
на время регистрации и проверки. Service2 маскирует этот сегмент в собственном
`django.request` error-log до записи на диск. Reverse proxy и APM также должны
маскировать callback URL в access/error-логах; URL нельзя публиковать или
добавлять в Git.

Секреты и временный access token хранятся только в зашифрованном виде. Для
стабильной расшифровки при ротации Django `SECRET_KEY` задайте отдельный
`COMMUNICATION_CREDENTIAL_KEY` одинаково на всех экземплярах приложения.

## Входящие и исходящие сообщения

Webhook проверяет секрет URL, тип события и ID подключённого аккаунта, игнорирует отражённые
исходящие события и идемпотентно сохраняет входящие сообщения по Avito message
ID. Неизвестные события принимаются без создания диалога, чтобы повторная
доставка провайдером не образовывала бесконечный цикл.

Исходящие текстовые сообщения отправляются периодической командой:

```bash
python manage.py send_avito_outbox --limit 100
```

Перед внешним вызовом команда атомарно переводит запись в `sending`, исключая
двойную отправку двумя параллельными процессами. Если процесс завершился после
вызова, но до ответа, запись остаётся в `sending` для ручной сверки: слепой
повтор мог бы создать дубль у клиента.

Команда получает access token по `client_credentials`, переиспользует его до
истечения и сохраняет только санитизированный код ошибки. Временные ошибки до
фактической отправки сообщения (timeout/503/rate limit при получении token)
автоматически возвращаются в очередь не более чем на три попытки. Неопределённый
результат уже начатой отправки остаётся в `sending` для ручной сверки. Вложения пока явно
помечаются ошибкой `attachments_require_provider_upload`: их нельзя считать
доставленными до реализации отдельного upload-вызова API Авито.
